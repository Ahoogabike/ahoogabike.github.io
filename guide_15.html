New Retailer IT Onboarding

From retailer request to test-ride booking, store finder and Shopify pickup — quick reference + detailed operating procedure.
Document ownerAhooga IT / Retail Operations
AudienceAhooga employee responsible for retailer onboarding
Version1.3 — 19 August 2026
ClassificationInternal use — contains operational and account-handling instructions
PurposeUse this procedure whenever a new retailer will sell Ahooga bikes and needs to accept test-ride bookings, appear in the Ahooga store finder and/or act as a Shopify pickup location.

✅ Part A — Quick operational checklist

Before you start

  • The retailer has a new, complete row in 0. Retailers Follow up File.xlsx. Every new retailer row must be processed.
  • You know the display name, full address, country, timezone and preferred language.
  • You have the retailer's current opening hours and booking notification email address.
  • You have checked the country. UK retailers require test-ride onboarding but must not be added to Shopify.
  • For a non-UK retailer, you know which Shopify location is the approved stock-copy reference. [CONFIRM process owner]
  • You have administrator access to Microsoft 365, Calendly setup, StoreRocket and Shopify.

Eight-step run sheet

1
Validate request: confirm test-ride and pickup scope in the retailer tracker.
2
Create mailbox: create Book Testride - <Retailer>; use booktestride<city-or-unique-name>@ahooga.bike; add IT@ahooga.bike; enable the identity only if required for Calendly; set a strong unique password.
3
Register account: add mailbox username, controlled credential reference and status to Calendly - MS Bookings.xlsx. Restrict access.
4
Create Calendly: sign up with Microsoft 365 on the Free plan; set profile language/timezone; create a 30-minute one-to-one event; use retailer opening hours; lock timezone; require phone; add bike-choice radio buttons; minimum notice 1 day.
5
Route bookings: set mailbox timezone; create a rule forwarding notifications@calendly.com to the retailer and to calendlybookings@ahooga.bike.
6
Publish StoreRocket: create/update the store, add the test-ride Calendly URL, publish and verify the public finder.
7
Enable Shopify: for non-UK retailers — create the location, enable pickup with 5+ days, enable Brussels AHOOGA Store under Store transfers, activate scoped inventory and set approved quantities. Skip Shopify for UK retailers.
8
Test + close: make a Calendly test booking; verify calendar and both forwards; test store finder; add a bike to cart and verify pickup; update both trackers.

Completion evidence

  • Public Calendly link saved
  • Test booking visible in shared mailbox calendar
  • Forward received by retailer
  • Forward received by automation mailbox
  • Store visible in public store finder
  • Calendly link opens from store finder
  • Non-UK retailer shown as Shopify pickup option, or UK recorded as not applicable
  • Correct products stocked at the non-UK location
  • Calendly - MS Bookings.xlsx updated
  • Store Locator column completed
  • Calendly up to date column completed
  • Added as Pickup column completed (or marked not applicable for a UK retailer)

🧰 Part C — Control, support and exceptions

Common issues and corrective actions

SymptomCorrective action
Microsoft sign-in failsCheck that sign-in is unblocked, the password is current, the identity is allowed to sign in and the required licence/security policy is satisfied.
Calendly shows wrong hoursCheck the event schedule, account timezone, locked event timezone and daylight-saving behaviour. Re-test in a private window.
Retailer gets no emailConfirm the exact recipient address, rule sender condition, junk/quarantine, and whether Calendly's sender has changed. Check the original mailbox notification first.
Automation does not triggerConfirm the notification arrived at calendlybookings@ahooga.bike, then review the related flow run using the booking timestamp.
Store not in finderCheck active/published state, geocoding/coordinates, country filters and caching. Test by city and postcode in a private window.
Wrong Calendly opensCorrect the StoreRocket booking URL and re-test from the public finder, not from Admin.
Pickup store not shownCheck pickup enablement, address, 5+ days setting, inventory at the location and availability for the exact selected variant.
Only some variants appearReturn to bulk inventory editing and verify that each tracked variant is stocked at the location with a positive approved quantity.
Duplicate locationStop. Confirm which record is authoritative with the e-commerce owner before renaming, merging or disabling anything.

Change and offboarding rules

95
Opening hours change: update Calendly availability and re-test the public booking page.
96
Retailer email changes: update the Outlook rule and send a new test booking.
97
Retailer moves: update the source file, mailbox timezone if needed, Calendly location, StoreRocket, Shopify address and public tests.
98
Retailer stops test rides: disable/pause the Calendly event and remove or replace the StoreRocket test-ride action after business approval.
99
Retailer stops pickup: disable pickup and inventory only after e-commerce approval; confirm that open orders and transfers are handled first.
100
Retailer closes: coordinate StoreRocket unpublication, Shopify deactivation, inventory/transfer handling and mailbox/Calendly retention. Do not delete records without an approved retention decision.
